## Latent issues noticed but not fixed

- ~~`XmlChangeLog::version()` returns `0.0.0` for `yars --version`.~~
  **Fixed 2026-05-16 in commit `28120eb`** — lifted the registrations
  into `XmlChangeLog::initialize()`, called early in
  `YarsConfiguration::init`. While there, also propagated CMake
  `PROJECT_VERSION` to C++ via `YARS_VERSION_STRING` so the output
  distinguishes binary from XML schema:
  `yars 0.8.7 (XML schema 0.8.41)`.
- **Shadow support — investigated 2026-05-18, deferred again.**
  Two techniques tried:
  - `SHADOWTYPE_STENCIL_MODULATIVE`: still segfaults in
    `ManualObject::getShadowVolumeRenderableList` (mParentNode
    null) on Ogre 14, same as the archive's 2026-02-02 finding.
  - `SHADOWTYPE_TEXTURE_MODULATIVE`: setup succeeds once the
    resource-group plumbing lands (per-platform `YARS_OGRE_MEDIA_DIR`,
    `OgreInternal` location for `spot_shadow_fade.dds`, null-checked
    edge-list loops), but the rendered frames come out empty —
    every frame is an I-frame at QP 0 with 100% mb-skip, captured
    .mp4 is 2.7 KB on macOS / 5 KB on Linux (vs ~1.4 MB without
    shadows). Reproduces on macOS arm64 with real GPU, so it's
    not an llvmpipe limitation.
  Most likely cause: RTSS isn't emitting a working depth-only
  shader variant for the shadow caster pass, and our generic
  RTSS-driven materials don't supply one. Re-enabling needs either
  custom `shadow_caster_material` entries in the .material scripts,
  or hand-written GL3+ shaders that bypass RTSS for the shadow path.
  All the plumbing (compile-time `YARS_OGRE_MEDIA_DIR`, resource-
  group registration, null-checked edge-list loops) is in tree as
  of `4be8fea`/`38a2845`, so the next attempt only needs the
  shader work.
- `OgreHandler` is still a singleton, and **stays that way**:
  pre-flight in openspec change `refactor-ogrehandler-singleton`
  (2026-05-18) found Ogre 14's `Singleton<Root>` base class
  asserts on a second instance
  (`OgreAssert(!msSingleton, "There can be only one singleton")`
  in `OgreSingleton.h:93`). Multi-Root is framework-blocked.
  A cosmetic YARS-side cleanup is still possible (drop the
  `instance()` accessor, hand ownership to `YarsViewModel` via
  `unique_ptr`) but deferred — it rearranges deck chairs around
  an immovable Ogre constraint and has no concrete driver.
- `_groundShape` in `Environment` is still a raw `btCollisionShape*`.
  Bullet has its own ownership protocol so this isn't urgent; consider
  `unique_ptr<btCollisionShape>` once we audit Bullet's deletion rules.
- ~~Dead `cleanupWindows()` in `YarsViewModel`~~
  **Deleted 2026-05-17 in commit `de634a8`.** The actual window
  cleanup happens in `YarsViewModel::run()` after the main loop
  exits; the dead function plus its `<algorithm>` include were just
  noise.

## CI / packaging state

**Updated 2026-05-16** — Linux + macOS CI are both green on the
post-modernization tree (Linux run `25967849242`, macOS run
`25967849230`). The earlier "disabled" claim was wrong: CI had been
re-enabled in commit `8cf76d8` after the Linux port verification, but
every push from v0.8.6 onwards was silently red because the runners
still installed `libboost-program-options-dev` / `catch2` instead of
`libcli11-dev` / `cli11`. Fixed in `ff451c8`.

Still-warning items, non-fatal:

- ~~CSV regression check is informational~~ **Done 2026-05-18 in
  openspec change `enforce-csv-reference-regression`.** Per-platform
  references (`xml/reference_logfile.linux-x86_64.csv` and
  `xml/reference_logfile.macos-arm64.csv`), both CI-generated, both
  sized to the 2 000-iter audit budget. Both runners' diffs are
  now bit-exact and fatal; the warning fallback is gone.
- ~~FFmpeg video capture missing .mp4~~ **Done 2026-05-18 in openspec
  change `fix-ffmpeg-mp4-capture`.** Capture had been silently broken
  for weeks behind a `::warning::`. Seven layered fixes (cwd-relative
  plugins.cfg, missing `--capture` flag, `YARS_USE_CAPTURE_VIDEO=OFF`
  default, missing avfilter/avdevice/avutil apt deps, FFmpeg 4 vs 5
  ABI break on `AVOutputFormat` constness, default
  `captureDirectory=video`/`captureName=yars.mp4`, segment-indexed
  `-NNNN` filename suffix). CI now uploads a 600×600 H.264 mp4 +
  ffprobe summary per run, and any future regression fails the step
  loudly rather than emitting a silent warning.
- ~~Node.js 20 deprecation~~ **Fixed 2026-05-16 in commit `d484389`** —
  bumped `actions/checkout` v4→v6, `actions/cache` v4→v5,
  `actions/upload-artifact` v4→v7. All three now ship Node 24.
  Warning is gone.
- ~~`freeimage` brew deprecation~~ **Done 2026-05-18 in commit
  `e2ec4ae`** (openspec change `migrate-freeimage-to-stbi`). Dropped
  libfreeimage from both runners + Ogre's FreeImage codec. Ogre's
  STBI plugin already covers all texture formats we use (audit
  found only `.png` and `.jpg` in `materials/`). Both CIs green
  on the post-migration tree.
