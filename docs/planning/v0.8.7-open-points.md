# v0.8.7 Open Points

Snapshot of work surfaced during the C++17 modernization batch
(2026-05-15) that was deferred, paused, or noticed-but-not-fixed.
Tagged at v0.8.7 / commit 87a6d32.

## Deferred features (archive material not yet brought forward)

- **C++20 evaluation** — bump `CMAKE_CXX_STANDARD` from 17 to 20, see
  what breaks, see what new features (designated initialisers, ranges,
  concepts, `<format>`) earn their keep.

(Shadow support was on this list at v0.8.7 but turns out to be an
Ogre-14 dead-end — see the "latent issues" section.)

## Skipped on purpose

- **`tests/integration/test_configuration.cpp`** (gtest port skipped) —
  the two singleton-existence tests would force `YarsConfiguration`
  to be linked into the test binary, which drags in `FollowCamera` /
  `CameraFactory` (live in YarsGUI), which drags in SDL2 + Ogre.
  Trivial assertions; not worth the link bloat. Reconsider only if
  YarsConfiguration ever becomes link-clean.
- **Mouse-camera changes** from the pre-force-push master — user
  explicitly excluded ("forget about mouse, this works better in the
  non-main version").

## Latent issues noticed but not fixed

- ~~`XmlChangeLog::version()` returns `0.0.0` for `yars --version`.~~
  **Fixed 2026-05-16 in commit `28120eb`** — lifted the registrations
  into `XmlChangeLog::initialize()`, called early in
  `YarsConfiguration::init`. While there, also propagated CMake
  `PROJECT_VERSION` to C++ via `YARS_VERSION_STRING` so the output
  distinguishes binary from XML schema:
  `yars 0.8.7 (XML schema 0.8.41)`.
- **Shadow support is a known Ogre-14 dead-end.** Archive commits
  `5c8ce3c` / `9231e10` / `a57f3c5` enable shadows; archive commit
  `9024f19` ("fix: Disable stencil shadows due to OGRE 14 crash")
  later disables them again because of a null `mParentNode` in
  `ManualObject::getShadowVolumeRenderableList`. Re-attempting needs
  either an Ogre upgrade or a different shadow path (texture-based
  rather than stencil).
- `OgreHandler` is still a singleton (`OgreHandler::instance()`) so
  it was excluded from the unique_ptr sweep. If we ever want to
  support multiple Ogre contexts (e.g., for Vulkan side-by-side) the
  singleton needs to go first.
- `_groundShape` in `Environment` is still a raw `btCollisionShape*`.
  Bullet has its own ownership protocol so this isn't urgent; consider
  `unique_ptr<btCollisionShape>` once we audit Bullet's deletion rules.
- `cleanupWindows()` in `YarsViewModel` was dead code at FOREACH-sweep
  time (latent UB: erase via a foreign iterator). The unique_ptr
  migration replaced the body with erase-remove; the function is
  still uncalled. Either wire it into the main loop or delete the
  declaration too.

## CI / packaging state

**Updated 2026-05-16** — Linux + macOS CI are both green on the
post-modernization tree (Linux run `25967849242`, macOS run
`25967849230`). The earlier "disabled" claim was wrong: CI had been
re-enabled in commit `8cf76d8` after the Linux port verification, but
every push from v0.8.6 onwards was silently red because the runners
still installed `libboost-program-options-dev` / `catch2` instead of
`libcli11-dev` / `cli11`. Fixed in `ff451c8`.

Still-warning items, non-fatal:

- The CSV regression check (`braitenberg_logging.xml` actual vs
  `xml/reference_logfile.csv`) is informational. The reference is
  10 002 rows from a 10 000-iteration run; CI bounds the run at 2 000
  iterations, so lengths differ. There's also minor signed-zero noise
  between Linux x86_64 (CI) and macOS arm64 (where the reference was
  captured). The "byte-identical" requirement in
  `openspec/specs/xml-xsd-validation/spec.md` is aspirational —
  enforcing it needs either a longer CI run or a platform-specific
  reference set.
- FFmpeg video capture step prints "no .mp4 produced (rc=0)" warning
  on some runs. The capture step exits clean but doesn't always
  produce an output file under xvfb/llvmpipe. Not load-bearing for
  the smoke test, but worth chasing if we ever want CI to verify
  rendered video end-to-end.
- ~~Node.js 20 deprecation~~ **Fixed 2026-05-16 in commit `d484389`** —
  bumped `actions/checkout` v4→v6, `actions/cache` v4→v5,
  `actions/upload-artifact` v4→v7. All three now ship Node 24.
  Warning is gone.
- `freeimage` is brew-deprecated (outstanding CVEs, requires patches
  to build). Homebrew disables it on **2027-01-10**. The macOS CI
  installs it via brew today. Either find a replacement Ogre image
  codec (Ogre's STBI plugin handles most of what we need) or accept
  the eventual brew breakage.
