# v0.8.7 Open Points

Snapshot of work surfaced during the C++17 modernization batch
(2026-05-15) that was deferred, paused, or noticed-but-not-fixed.
Tagged at v0.8.7 / commit 87a6d32.

## Deferred features (archive material not yet brought forward)

- **Shadow support** — archive commits `a57f3c5`, `9231e10`, `5c8ce3c`
  add Ogre shadow rendering. Visual feature; needs GUI verification
  + screenshot comparison.
- **C++20 evaluation** — bump `CMAKE_CXX_STANDARD` from 17 to 20, see
  what breaks, see what new features (designated initialisers, ranges,
  concepts, `<format>`) earn their keep.

## Skipped on purpose

- **`tests/integration/test_configuration.cpp`** (gtest port skipped) —
  the two singleton-existence tests would force `YarsConfiguration`
  to be linked into the test binary, which drags in `FollowCamera` /
  `CameraFactory` (live in YarsGUI), which drags in SDL2 + Ogre.
  Trivial assertions; not worth the link bloat. Reconsider only if
  YarsConfiguration ever becomes link-clean.
- **Mouse-camera changes** from the pre-force-push master — user
  explicitly excluded ("forget about mouse, this works better in the
  non-main version").

## Latent issues noticed but not fixed

- `XmlChangeLog::version()` returns `0.0.0` for `yars --version`. The
  CMake `PROJECT_VERSION` (0.8.7) is unrelated; the XML changelog
  hasn't been initialised when `--version` fires. Separate from CLI11
  work, predates this session.
- `OgreHandler` is still a singleton (`OgreHandler::instance()`) so
  it was excluded from the unique_ptr sweep. If we ever want to
  support multiple Ogre contexts (e.g., for Vulkan side-by-side) the
  singleton needs to go first.
- `_groundShape` in `Environment` is still a raw `btCollisionShape*`.
  Bullet has its own ownership protocol so this isn't urgent; consider
  `unique_ptr<btCollisionShape>` once we audit Bullet's deletion rules.
- `cleanupWindows()` in `YarsViewModel` was dead code at FOREACH-sweep
  time (latent UB: erase via a foreign iterator). The unique_ptr
  migration replaced the body with erase-remove; the function is
  still uncalled. Either wire it into the main loop or delete the
  declaration too.
