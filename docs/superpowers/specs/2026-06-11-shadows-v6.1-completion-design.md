# Shadows v6.1 — completing the texture-shadow pipeline

**Date:** 2026-06-11
**Status:** approved (user selected Option A: complete v6)
**Goal doc:** `docs/planning/shadow_goal.md` (acceptance criteria 1–6)
**Prior state:** `docs/planning/shadows_state.md` (v6, 2026-05-22)

## Problem

The v6 shadow pipeline (`SHADOWTYPE_TEXTURE_MODULATIVE` + custom GLSL
caster/receiver + `ShadowMapper` pushing the shadow camera's
`proj × view` from C++, bypassing Ogre 14's broken
`texture_worldviewproj_matrix` auto-param on macOS arm64 GL3+ core) is
architecturally sound — it is the only approach that has ever placed
shadows correctly on this stack. But verified at HEAD (2026-06-11,
frame captures):

- `hexapod_mpi.xml`: good soft shadow ✅
- `braitenberg.xml`: floor uniformly lit; no visible robot shadow,
  faint wall strip on one side only ⚠️
- `falling_objects.xml`: no shadows at all ❌
- Acceptance criterion 3 (shadow on a non-floor receiver, e.g. a wall
  obstacle): never tested; no test scene exists ❌

Three concrete defects cause this:

1. **`FocusedShadowCameraSetup` is eye-camera-dependent.** It fits the
   shadow frustum to the viewer's view, so coverage shifts when the
   camera moves and sparse-caster scenes get a tight frustum that
   misses most of the floor.
2. **8-bit depth.** The caster writes depth into the R channel of a
   `PF_R8G8B8` texture — 256 depth levels over a 200-unit frustum.
   The shadow bias (0.0015) is smaller than one depth quantum
   (1/256 ≈ 0.0039), so the depth compare is noise-dominated and
   subtle shadows vanish.
3. **Hard binary shadow test, `filtering none`.** No PCF — aliased
   edges, unlike the soft penumbra in `hexapod_reference.png`.

## Design

### 1. World-anchored shadow camera

Replace `FocusedShadowCameraSetup` with the already-written but unused
`YarsFixedShadowCameraSetup` (`OgreHandler.cpp:42`), modified:

- Ortho frustum half-extent derived from the ground/floor dimensions
  at scene load, plus ~20 % margin; fallback 25 m when no ground
  dimensions are available. (Previously hardcoded 24×24.)
- Light-aligned at `(-1,-1,-1)`, positioned at `-lightDir × 50` looking
  at the origin, ignoring the eye camera entirely (unchanged from the
  existing dead-code implementation).

This guarantees full-arena coverage in every scene, removes
camera-dependent drift, and keeps texel density stable
(50 m / 2048 ≈ 2.4 cm/texel — acceptable once PCF smooths edges).

**Flagged verification (do FIRST):** the receiver shader currently
compensates for Ogre's per-render-target FBO Y-flip
(`uv.y = 1.0 - uv.y`), which is baked into `getProjectionMatrix()` for
Ogre-driven projections. With `setCustomProjectionMatrix`, Ogre may
return the custom matrix verbatim (no flip). Step one of
implementation is a diagnostic capture to establish which convention
holds; the shader then matches it. Do not guess — the attempts log
(`docs/planning/shadows_attempts_log.md`) documents six failed
flip/swap guesses.

### 2. Depth precision

`setShadowTexturePixelFormat(Ogre::PF_FLOAT32_R)`. The caster shader
already outputs float depth in R; only the format line changes.
Re-tune `shadowBias` afterwards (expect ~0.0005 or smaller; consider
slope-scaled only if acne appears).

### 3. PCF soft edges

9-tap (3×3) PCF in `materials/shadow_receiver.frag`, using
`textureSize(shadowMap, 0)` for texel offsets (GLSL 330, no new
uniforms). Average the 9 binary compares into a shadow factor;
final modulation `mix(shadowDarkness, 1.0, factor)`.
`shadowDarkness` stays 0.35. Keep `filtering none` in the material
(PCF does its own filtering; linear filtering of raw depth is
incorrect without `sampler2DShadow`).

### 4. Acceptance scene for criterion 3

New `xml/hexapod_shadow_test.xml`: copy of `hexapod_mpi.xml`
(passive joints, no controller dependency) plus a white box obstacle
placed adjacent to the robot so leg/body shadows fall on the
obstacle's face, mirroring `hexapod_reference.png`.

### 5. Validation gate (all must pass)

1. `braitenberg.xml` capture: robot shadow visible and offset along
   the light direction; wall shadows along wall bases; no
   double-darkening; floor texture visible through shadows.
2. `falling_objects.xml` capture: smooth elliptical ball shadows,
   no mesh pattern.
3. `hexapod_shadow_test.xml` capture: distinct per-leg shadows; shadow
   visible on the obstacle face, not just the floor.
4. CSV regression: `braitenberg_logging.xml` 2000 iterations
   byte-identical to `xml/reference_logfile.macos-arm64.csv`.
5. `yars_tests`: 35/35.
6. Clean build, no new warnings; GUI run works (not only `--nogui` /
   capture mode).

Visual checks use zoomed crops (PIL), since shadows can be subtle at
full-frame scale.

## Out of scope (YAGNI)

improvements beyond bias tuning, stencil shadow volumes, OgreNext.

## Risks

- **Y-flip under custom projection** — mitigated by diagnostic-first
  step (see §1).
- **`PF_FLOAT32_R` RTT support** — GL3+ core guarantees R32F color
  attachments; if Ogre's GL3+ RS rejects it, fall back to
  `PF_FLOAT16_R` (65k levels, still ≫ 256).
- **Frustum too coarse in huge scenes** — half-extent is clamped to
  ground size; if a scene's ground is enormous, shadow resolution
  drops. Accepted; revisit with cascades only if it ever bites.
