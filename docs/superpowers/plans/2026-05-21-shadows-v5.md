# Shadows v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get visible, correct, world-anchored shadows working in YARS — robot + walls cast shadows on the floor — for both `braitenberg.xml` and `falling_objects.xml`, validated by frame capture.

**Architecture:** Six-step escalation from cheap diagnostics to a custom shadow-mapping pipeline that bypasses Ogre's broken `texture_worldviewproj_matrix` auto-param. Steps 1–4 are short experiments that *might* fix the issue inside Ogre's framework. If 1–4 fail, step 5 is a self-contained custom top-down render-to-texture shadow pipeline (~250 LOC) that has no dependency on Ogre's shadow framework. Step 6 is a guaranteed-to-work planar-projection backstop.

**Tech Stack:** Ogre 14.x + RTSS (GL3+ core) on macOS arm64, C++17, custom GLSL fragment+vertex shaders, Bullet Physics (untouched by this work), CMake 3.16+.

**Reference docs (read first):**
- `/Volumes/Eregion/projects/yars/docs/planning/shadows_attempts_log.md` — full history of failed attempts and diagnostics
- `/Volumes/Eregion/projects/yars/docs/planning/shadows_v5_plan.md` — the synthesised research and rationale (this plan is the concrete execution)
- `/Volumes/Eregion/projects/yars/CLAUDE.md` — YARS coding/build/test rules

**Acceptance criteria for the whole plan (NOT per task):**
1. `braitenberg.xml`: robot casts a clear shadow on the floor in the light direction. Shadow is world-anchored (doesn't slide when the eye camera moves).
2. `falling_objects.xml`: falling balls cast clear shadows that follow the balls, not the camera.
3. CSV regression: `diff $logfile xml/reference_logfile.macos-arm64.csv` returns 0 lines for both 1000- and 2000-iteration runs.
4. `yars_tests` passes 35/35 (or whatever the current count is).
5. Build is clean: `make -j4` in `./build` succeeds with no new warnings.
6. No crashes, no rendering glitches in adjacent features (overlay text, sensor visualizations, video capture).

**Process rules:**
- ALWAYS compile and run yars in `./build` (per `CLAUDE.md`).
- After every code change: rebuild, run with capture, extract a late frame as PNG, **visually verify** before moving on.
- Use a timeout when invoking yars: `timeout 60 ./bin/yars ...`.
- Never claim success until a captured PNG shows the expected result.
- Don't start a new step until the previous step's commit is in place.

**Out of scope (don't do):**
- Porting to OgreNext, switching to Vulkan/Metal, replacing the renderer entirely. Documented in `shadows_v5_plan.md` section 3 as multi-week investments.
- "While you're at it" refactors — the goal is shadows, not cleanup.

- [ ] **Step 2.1: Find the shadow texture render target accessor**

- [ ] **Step 2.2: Add diagnostic print to OgreHandler::step()**

Edit `src/yars/view/gui/OgreHandler.cpp` near line 506 (inside `step()`, after `_root->renderOneFrame();`):

```cpp
// DIAGNOSTIC (shadows v5, step 2): confirm whether the shadow RTT
// reports Y-flip. If false, the bias-matrix cancellation in
// AutoParamDataSource::getTextureViewProjMatrix is silently wrong
// on this platform — worth filing upstream.
static bool flipReported = false;
if (!flipReported) {
    try {
        if (_sceneManager->getShadowTextureCount() > 0) {
            Ogre::TexturePtr tex = _sceneManager->getShadowTexture(0);
            if (tex) {
                Ogre::RenderTarget *rt = tex->getBuffer()->getRenderTarget();
                std::cerr << "SHADOW-RTT-FLIP: requiresTextureFlipping="
                          << (rt && rt->requiresTextureFlipping() ? "true" : "false")
                          << " w=" << (rt ? rt->getWidth() : 0)
                          << " h=" << (rt ? rt->getHeight() : 0)
                          << " name=" << tex->getName()
                          << std::endl;
                flipReported = true;
            }
        }
    } catch (const std::exception &ex) {
        std::cerr << "SHADOW-RTT-FLIP failed: " << ex.what() << std::endl;
        flipReported = true;
    }
}
```

## Step 5: Custom top-down RTT shadow pipeline (Approach A)

**Purpose:** Bypass Ogre's broken `texture_worldviewproj_matrix` auto-param and Ogre's whole shadow framework. Build a self-contained top-down render-to-texture shadow with hand-rolled UVs. This is the main event — ~250 LOC, but guaranteed to work because every step is in our code.

**Architecture overview:**

```
Frame N rendering:
  1. ShadowMapper::preRender() — invoked from OgreHandler::step()
     a. Set every visible entity's material to "yars-shadow-cast" variant (black opaque)
     b. Render the scene from a top-down ortho camera into shadow_rt
     c. Restore original materials
  2. Eye camera renders the scene normally
     a. Ground material uses YARSGroundShadowed.material
     b. Its fragment shader samples shadow_rt with uv = worldXZ-derived
     c. Multiplies colour by mix(SHADOW_STRENGTH, 1.0, shadowSample)
```

**Coordinate system reminder:**
- YARS world is Z-up, Ogre world is Y-up (converted via `YARS_TO_OGRE` macro)
- Scene root has a -90° X rotation (see `SceneGraph.cpp:49-50`) but the directional light is NOT under the rotated root
- Light direction is hardcoded `(-1, -1, -1)` in Ogre coords
- Arena is ~8×8 m in YARS coords; ground mesh is 50×50

**Design decisions (locked in):**
- Top-down ortho camera, not aligned to light direction. Walls cast slightly extruded shadows on the floor when the floor samples a top-down silhouette. Acceptable trade-off for v1.
- Shadow RTT format: `PF_R8` — single channel, 0 = caster, 255 = no caster. Cheap.
- Shadow RTT size: 1024² for v1; we can bump to 2048² later.
- Arena bounds: hardcoded for v1 — `(-6, -6)` to `(+6, +6)` in Ogre XZ. Generalize later.
- `RenderTargetListener` swaps material scheme. Define a new scheme `"yars-shadow-cast"` whose technique for each YARS material is a single black-on-white pass.

### 5b: ShadowMapper — RTT + camera + listener

- [ ] **Step 5b.1: Write the ShadowMapper header**

Create `src/yars/view/gui/ShadowMapper.h`:

```cpp
#ifndef YARS_VIEW_GUI_SHADOW_MAPPER_H
#define YARS_VIEW_GUI_SHADOW_MAPPER_H

#include <OGRE/OgreCamera.h>
#include <OGRE/OgreRenderTargetListener.h>
#include <OGRE/OgreTexture.h>
#include <OGRE/OgreMaterialManager.h>

namespace yars {

/**
 * Custom top-down render-to-texture shadow pipeline.
 *
 * Ogre 14's built-in texture_worldviewproj_matrix auto-param is broken
 * on GL3+ core (see docs/planning/shadows_attempts_log.md), so we
 * sidestep Ogre's shadow framework entirely:
 *
 *   1. Create a dedicated 1024x1024 R8 RTT (`shadow_rt`) above the
 *      arena, with an orthographic camera looking straight down.
 *   2. Each frame: render the scene into the RTT with every entity
 *      painted black (silhouette pass).
 *   3. The ground material (`YARS/GroundShadowed`) samples this RTT
 *      using `uv = (worldXZ - arenaMin) / arenaSize` — UV math is in
 *      our shader, not in Ogre's auto-param.
 *
 * The light direction is approximated by a top-down ortho. For the
 * YARS scene (8x8 arena, ~0.5m wall height, single directional light)
 * this is visually close enough; walls cast small shadow strips on
 * the floor exactly where they would under the directional light.
 */
class ShadowMapper : public Ogre::RenderTargetListener
{
public:
    /**
     * Configures the RTT and orthographic camera. The supplied scene
     * manager must already exist and have a viewport.
     *
     * @param sm The Ogre scene manager owning the scene to be shadowed.
     * @param arenaSize Arena half-extent in Ogre world units (e.g. 6.0
     *                  for a 12x12 m arena centered on origin).
     */
    ShadowMapper(Ogre::SceneManager *sm, float arenaSize);
    ~ShadowMapper() override;

    /// Force a shadow re-render this frame. Call from OgreHandler::step.
    void update();

    /// Name of the RTT texture (so ground material can reference it).
    static const char *RTT_NAME;
    /// Name of the shadow-cast material scheme.
    static const char *CAST_SCHEME;

    // RenderTargetListener overrides
    void preRenderTargetUpdate(const Ogre::RenderTargetEvent &evt) override;
    void postRenderTargetUpdate(const Ogre::RenderTargetEvent &evt) override;

private:
    Ogre::SceneManager *_sm;
    float _arenaSize;
    Ogre::TexturePtr _rtt;
    Ogre::Camera *_shadowCam;
    Ogre::SceneNode *_shadowCamNode;
    Ogre::Viewport *_shadowVp;
    Ogre::String _previousScheme; // restored in postRenderTargetUpdate
};

} // namespace yars

#endif
```

- [ ] **Step 5b.2: Write the ShadowMapper implementation**

Create `src/yars/view/gui/ShadowMapper.cpp`:

```cpp
#include "ShadowMapper.h"

#include <OGRE/OgreHardwarePixelBuffer.h>
#include <OGRE/OgreRenderTexture.h>
#include <OGRE/OgreSceneManager.h>
#include <OGRE/OgreSceneNode.h>
#include <OGRE/OgreTextureManager.h>
#include <OGRE/OgreViewport.h>

#include <iostream>

namespace yars {

const char *ShadowMapper::RTT_NAME = "YarsShadowRTT";
const char *ShadowMapper::CAST_SCHEME = "yars-shadow-cast";

ShadowMapper::ShadowMapper(Ogre::SceneManager *sm, float arenaSize)
    : _sm(sm), _arenaSize(arenaSize), _shadowCam(nullptr),
      _shadowCamNode(nullptr), _shadowVp(nullptr)
{
    // 1) Create the RTT.
    _rtt = Ogre::TextureManager::getSingleton().createManual(
        RTT_NAME,
        Ogre::ResourceGroupManager::DEFAULT_RESOURCE_GROUP_NAME,
        Ogre::TEX_TYPE_2D,
        1024, 1024,
        0, // no mipmaps
        Ogre::PF_R8,
        Ogre::TU_RENDERTARGET);

    Ogre::RenderTarget *rt = _rtt->getBuffer()->getRenderTarget();
    rt->setAutoUpdated(false); // we drive it manually each frame

    // 2) Create the top-down orthographic camera.
    _shadowCam = _sm->createCamera("YarsShadowCam");
    _shadowCam->setProjectionType(Ogre::PT_ORTHOGRAPHIC);
    // Ortho window covers [-arenaSize, +arenaSize] in both X and Z
    // when viewed from above (Ogre world).
    _shadowCam->setOrthoWindow(_arenaSize * 2.0f, _arenaSize * 2.0f);
    _shadowCam->setNearClipDistance(0.5f);
    _shadowCam->setFarClipDistance(100.0f);
    // Camera looks straight down (-Y in Ogre world).
    _shadowCamNode = _sm->getRootSceneNode()->createChildSceneNode("YarsShadowCamNode");
    _shadowCamNode->setPosition(0.0f, 50.0f, 0.0f);
    _shadowCamNode->lookAt(Ogre::Vector3::ZERO, Ogre::Node::TS_WORLD);
    _shadowCamNode->attachObject(_shadowCam);

    // 3) Attach a viewport that clears to white (1,1,1 = "no shadow").
    _shadowVp = rt->addViewport(_shadowCam);
    _shadowVp->setBackgroundColour(Ogre::ColourValue::White);
    _shadowVp->setClearEveryFrame(true);
    _shadowVp->setOverlaysEnabled(false);
    _shadowVp->setShadowsEnabled(false);

    // 4) Install listener so we can swap material schemes around the
    // shadow pass.
    rt->addListener(this);

    std::cerr << "ShadowMapper: initialised RTT " << RTT_NAME
              << " (1024^2 R8), ortho " << _arenaSize * 2.0f
              << " x " << _arenaSize * 2.0f << std::endl;
}

ShadowMapper::~ShadowMapper()
{
    if (_rtt) {
        Ogre::RenderTarget *rt = _rtt->getBuffer()->getRenderTarget();
        if (rt) rt->removeListener(this);
    }
    if (_shadowCamNode) {
        _shadowCamNode->detachAllObjects();
        _sm->getRootSceneNode()->removeAndDestroyChild(_shadowCamNode);
    }
    if (_shadowCam) {
        _sm->destroyCamera(_shadowCam);
    }
    if (_rtt) {
        Ogre::TextureManager::getSingleton().remove(_rtt);
    }
}

void ShadowMapper::update()
{
    if (_rtt) {
        _rtt->getBuffer()->getRenderTarget()->update();
    }
}

void ShadowMapper::preRenderTargetUpdate(const Ogre::RenderTargetEvent &)
{
    // Swap viewport material scheme: every material is rendered using
    // its "yars-shadow-cast" technique (a single black opaque pass).
    // Materials without that technique use the MaterialManager listener
    // to auto-generate one.
    _previousScheme = Ogre::MaterialManager::getSingleton().getActiveScheme();
    Ogre::MaterialManager::getSingleton().setActiveScheme(CAST_SCHEME);
    if (_shadowVp) _shadowVp->setMaterialScheme(CAST_SCHEME);
}

void ShadowMapper::postRenderTargetUpdate(const Ogre::RenderTargetEvent &)
{
    Ogre::MaterialManager::getSingleton().setActiveScheme(_previousScheme);
}

} // namespace yars
```

### 5c: Auto-generate shadow-cast technique for arbitrary materials

The challenge: every material in YARS needs to have a `technique { scheme yars-shadow-cast; ... }` variant, so when the ShadowMapper swaps the active scheme to `yars-shadow-cast`, every entity renders with our black silhouette material. We don't want to manually add this to every `.material` file.

Solution: use a `MaterialManager::Listener` (similar to YARS's existing `SGTechniqueResolverListener`) that intercepts requests for materials in the `yars-shadow-cast` scheme and returns a generated technique.

- [ ] **Step 5c.1: Add ShadowCastSchemeListener**

In `src/yars/view/gui/ShadowMapper.cpp`, ADD a nested helper class (or as a separate listener defined here). It implements `MaterialManager::Listener::handleSchemeNotFound`:

```cpp
namespace {

/// When the active scheme is "yars-shadow-cast" and a material doesn't
/// have a technique tagged with that scheme, return a copy of the
/// YARS/CustomShadowCast material's technique. This avoids having to
/// manually annotate every .material file.
class ShadowCastSchemeListener : public Ogre::MaterialManager::Listener
{
public:
    Ogre::Technique *handleSchemeNotFound(
        uint16_t /*schemeIndex*/,
        const Ogre::String &schemeName,
        Ogre::Material *originalMaterial,
        uint16_t /*lodIndex*/,
        const Ogre::Renderable * /*rend*/) override
    {
        if (schemeName != ShadowMapper::CAST_SCHEME) return nullptr;
        if (originalMaterial->getName() == "YARS/CustomShadowCast") return nullptr;

        Ogre::MaterialPtr castMat = Ogre::MaterialManager::getSingleton()
            .getByName("YARS/CustomShadowCast");
        if (!castMat) return nullptr;
        castMat->load();
        // Return the first technique of YARS/CustomShadowCast.
        return castMat->getNumTechniques() > 0 ? castMat->getTechnique(0) : nullptr;
    }
};

static ShadowCastSchemeListener *gShadowCastListener = nullptr;

} // anonymous namespace
```

### 5d: Ground receiver material that samples the RTT

- [ ] **Step 5d.1: Create the receiver vertex shader**

Create `materials/yars_ground_shadowed.vert`:

```glsl
#version 330 core

uniform mat4 worldViewProjMatrix;
uniform mat4 worldMatrix;

in vec4 vertex;
in vec4 uv0;

out vec2 texUV;       // diffuse texture (ground.jpg) UV
out vec2 shadowUV;    // shadow RTT UV — world-XZ-derived

// Arena half-extent in Ogre world units. Match
// ShadowMapper(arenaSize=6.0f) from C++.
const float ARENA_HALF = 6.0;

void main() {
    gl_Position = worldViewProjMatrix * vertex;

    // Diffuse UV from the mesh's existing UV0.
    texUV = uv0.xy;

    // Shadow UV from the vertex's world-space XZ position. The shadow
    // camera is top-down ortho covering [-ARENA_HALF, +ARENA_HALF] in
    // both X and Z, so:
    //   worldXZ in [-ARENA_HALF, +ARENA_HALF] -> uv in [0, 1]
    vec4 worldPos = worldMatrix * vertex;
    shadowUV = (worldPos.xz / (ARENA_HALF * 2.0)) + vec2(0.5, 0.5);
}
```

- [ ] **Step 5d.2: Create the receiver fragment shader**

Create `materials/yars_ground_shadowed.frag`:

```glsl
#version 330 core

uniform sampler2D diffuseMap;     // ground.jpg
uniform sampler2D shadowMap;      // YarsShadowRTT (R8: 0=caster, 255=clear)

in vec2 texUV;
in vec2 shadowUV;

out vec4 FragColor;

const float SHADOW_STRENGTH = 0.4; // 0=full shadow, 1=no shadow

void main() {
    vec3 diffuse = texture(diffuseMap, texUV).rgb;

    // Out-of-arena: no shadow (border-color sample). Guard.
    float occluder = 1.0;
    if (shadowUV.x >= 0.0 && shadowUV.x <= 1.0 &&
        shadowUV.y >= 0.0 && shadowUV.y <= 1.0) {
        occluder = texture(shadowMap, shadowUV).r;
    }

    // occluder == 1.0 -> no shadow; 0.0 -> full shadow.
    float modulation = mix(SHADOW_STRENGTH, 1.0, occluder);
    FragColor = vec4(diffuse * modulation, 1.0);
}
```

Note the Y-flip caveat: GL FBOs render bottom-up but our shader writes top-down. If the resulting shadow placement is mirrored on Y, swap to `shadowUV.y = 1.0 - shadowUV.y` in the vertex shader. We'll see this in Step 5d.6.

```cpp
#include "PlanarShadowProjector.h"

namespace yars {

Ogre::Matrix4 planarShadowMatrix(const Ogre::Plane &plane,
                                 const Ogre::Vector4 &light)
{
    // Reference: SIGGRAPH 97 "Projection Shadows" notes.
    // https://www.opengl.org/archives/resources/code/samples/advanced/advanced97/notes/node100.html
    //
    //   M[i][j] = (i==j ? n.l : 0) - l[i] * planeCoeffs[j]
    //
    // with planeCoeffs = (nx, ny, nz, d) and l = (lx, ly, lz, lw).

    float planeCoeffs[4] = {
        plane.normal.x, plane.normal.y, plane.normal.z, plane.d};
    float l[4] = {light.x, light.y, light.z, light.w};
    float ndotl = planeCoeffs[0]*l[0] + planeCoeffs[1]*l[1]
                + planeCoeffs[2]*l[2] + planeCoeffs[3]*l[3];

    Ogre::Matrix4 m;
    for (int i = 0; i < 4; ++i)
        for (int j = 0; j < 4; ++j)
            m[i][j] = (i == j ? ndotl : 0.0f) - l[i] * planeCoeffs[j];
    return m;
}

} // namespace yars
```

## Notes on the implementation

- **Why not use `setShadowTechnique(SHADOWTYPE_TEXTURE_*)` and just give Ogre our custom RTT?** Ogre's shadow framework hard-wires its own RTT creation and caster pass. Our pipeline is fundamentally different (one camera, one pass, one RTT, hand-rolled UVs) so it's cleaner to keep `SHADOWTYPE_NONE` and run independently.
- **Why R8 format for the RTT?** The receiver only needs a single scalar (caster vs no-caster). R8 is the smallest, fastest format. If we later need soft shadows or PCF, switch to R8 + a blur pass.
- **Why ortho and not directional-light-aligned?** For directional light from `(-1,-1,-1)` projected onto a Y-up floor, the shadow on the floor is the silhouette of the caster *projected along the light direction*. Top-down ortho is a different projection — but for tall casters in a flat arena the difference is small (walls cast strips of width ~ wall_height). If we want true directional shadows later, change the shadow camera's basis from `(0,1,0)→(0,-1,0)` to the light vector. The math in `yars_ground_shadowed.vert` would then need to be `worldXZ` post-light-projection, not raw worldXZ — but the structural pattern is the same.
- **What if the arena center isn't world origin?** It is in YARS (per `SceneGraphEnvironmentNode`). If that ever changes, the constant `vec2(0.5, 0.5)` in the receiver vertex shader needs to come from a uniform.
