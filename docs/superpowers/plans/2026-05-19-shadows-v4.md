# Shadows v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable real dynamic directional shadows in YARS by adding a hand-written GLSL 330-core shadow-caster material that bypasses RTSS, then switching the scene to `SHADOWTYPE_TEXTURE_MODULATIVE`.

**Architecture:** Three layers. (1) A new `materials/YARSShadowCaster.material` script with explicit `vertex_program_ref`/`fragment_program_ref` pointing at two new GLSL files — RTSS never fires for this material. (2) `MaterialManager` sets `pass->setShadowCasterMaterial("YARS/TextureShadowCaster")` on every receiver pass, gated on `params.castShadows`. (3) `OgreHandler::__setScene` enables `SHADOWTYPE_TEXTURE_MODULATIVE` with 1024² texture, far=50, mid-grey shadow colour. The existing resource plumbing (`YARS_OGRE_MEDIA_DIR`, `OgreInternal` group, null-checked edge-list loops) already supports this technique — no infrastructure changes needed.

**Tech Stack:** C++17, Ogre 14, GLSL 330 core, CMake 3.16+, SDL2.

**Spec reference:** `docs/superpowers/specs/2026-05-19-shadows-v4-design.md`

**Testing note:** This is rendering code with no unit-test harness. Acceptance is build-clean + headless CSV regression + GUI smoke (must print "Good bye") + **mandatory PNG visual verification** before any commit claims success. Byte counts on captured mp4s are NOT acceptance — see v3 failure (commit a10c1b1) for the lesson.

## Task 1: Add the GLSL caster shaders and material script

**Files:**
- Create: `materials/shadow_caster.vert`
- Create: `materials/shadow_caster.frag`
- Create: `materials/YARSShadowCaster.material`

- [ ] **Step 1: Create the vertex shader**

Create `materials/shadow_caster.vert`:

```glsl
#version 330 core

uniform mat4 worldViewProjMatrix;

in vec4 vertex;

void main()
{
    gl_Position = worldViewProjMatrix * vertex;
}
```

This mirrors the existing `materials/simple.vert` style. The `in vec4 vertex` attribute is what Ogre binds for `OGRE_AUTO_ATTRIBUTE_INDEX_POSITION` automatically. `worldViewProjMatrix` is filled by the auto-param `worldviewproj_matrix` declared in the .material below.

- [ ] **Step 2: Create the fragment shader**

Create `materials/shadow_caster.frag`:

```glsl
#version 330 core

out vec4 FragColor;

void main()
{
    FragColor = vec4(0.0, 0.0, 0.0, 1.0);
}
```

Opaque black. For `SHADOWTYPE_TEXTURE_MODULATIVE`, the shadow texture stores light visibility — black means "occluded".

- [ ] **Step 3: Create the material script**

Create `materials/YARSShadowCaster.material`:

```
vertex_program YARS/ShadowCasterVP glsl
{
  source shadow_caster.vert
  default_params
  {
    param_named_auto worldViewProjMatrix worldviewproj_matrix
  }
}

fragment_program YARS/ShadowCasterFP glsl
{
  source shadow_caster.frag
}

material YARS/TextureShadowCaster
{
  receive_shadows off
  technique
  {
    pass
    {
      vertex_program_ref YARS/ShadowCasterVP {}
      fragment_program_ref YARS/ShadowCasterFP {}
    }
  }
}
```

Note: `receive_shadows off` prevents the caster material itself from being treated as a shadow receiver if it ever gets used directly. The explicit `vertex_program_ref`/`fragment_program_ref` means RTSS's `SGTechniqueResolverListener` never fires for this material (it only fires when a technique lacks an RTSS scheme; this technique has explicit shaders and is its own scheme).

- [ ] **Step 4: Build to confirm material script parses**

Run:
```bash
cd build && make -j8 2>&1 | tail -5
```

Expected: clean build. The material files aren't compiled into the binary; they're loaded at runtime. Build success only confirms no C++ changes broke anything.

- [ ] **Step 5: Smoke-test that Ogre loads the material**

Run:
```bash
cd build && timeout 5 ./bin/yars --xml ../xml/braitenberg_logging.xml --iterations 100 --nogui 2>&1 | grep -iE "shadow_caster|YARS/TextureShadowCaster|YARS/ShadowCaster|error|fail" | head -20
```

Expected: no errors involving the new material/shader names. If GLSL compiles eagerly, we'd see a "Compiled shader" or similar; if not, it's silently deferred (Ogre's default for GLSL is deferred). Sensor lines are unchanged (shadows aren't enabled yet).

- [ ] **Step 6: Commit**

```bash
git add materials/shadow_caster.vert materials/shadow_caster.frag materials/YARSShadowCaster.material
git commit -m "$(cat <<'EOF'
feat(gui): add YARS/TextureShadowCaster material with explicit GLSL

Hand-rolled depth-only shadow caster: a vertex shader that just
transforms position and a fragment shader that writes opaque black.
Together they form YARS/TextureShadowCaster — a material whose passes
have explicit vertex_program_ref/fragment_program_ref so the RTSS
auto-technique listener never fires on them.

This is the missing piece from shadows v2/v3: those attempts relied on
Ogre's stock Ogre/TextureShadowCaster, which is a fixed-function
```

## Task 2: Wire MaterialManager to set the caster material on receivers

**Files:**
- Modify: `src/yars/view/gui/MaterialManager.cpp`

- [ ] **Step 1: Update `_createBasicRTSSMaterial` to set the shadow caster**

In `src/yars/view/gui/MaterialManager.cpp`, after the existing texture-unit creation block in `_createBasicRTSSMaterial` (around line 272, right before the closing brace of the function), add:

```cpp
    // Wire shadow caster: when SHADOWTYPE_TEXTURE_MODULATIVE is active,
    // Ogre substitutes this material in the caster pass. Caster has explicit
    // GLSL programs so it bypasses RTSS. Skip if this material itself is the
    // caster (avoid recursion) or castShadows was disabled by the caller.
    if (params.castShadows && name != "YARS/TextureShadowCaster") {
      pass->setShadowCasterMaterial("YARS/TextureShadowCaster");
    }
```

This is one new block at the bottom of `_createBasicRTSSMaterial`, just before the trailing `}` of the function (after the `if (!params.diffuseTexture.empty()) { ... }` block).

- [ ] **Step 2: Update `createRTSSForLegacyMaterials` to also set caster on RTSS-generated passes**

In `src/yars/view/gui/MaterialManager.cpp`, inside the `_createRTSS` lambda, after the existing `Copy blend/depth settings from base technique` block (right after the `if (baseTech && rtssTech && baseTech != rtssTech)` block, before the closing `};` of the lambda — around line 203), add:

```cpp
        // Set the YARS-owned GLSL shadow caster on every RTSS-generated pass.
        // Without this, the caster pass falls back to RTSS-generated shaders
        // which don't produce a working depth-only variant (see shadows v3
        // failure, commit a10c1b1). Skip the caster material itself.
        if (rtssTech && material->getName() != "YARS/TextureShadowCaster") {
          for (unsigned short p = 0; p < rtssTech->getNumPasses(); ++p) {
            Ogre::Pass *rp = rtssTech->getPass(p);
            if (rp && rp->getShadowCasterMaterial().get() == nullptr) {
              rp->setShadowCasterMaterial("YARS/TextureShadowCaster");
            }
          }
        }
```

Note: `Pass::getShadowCasterMaterial()` returns a `MaterialPtr` (a shared_ptr). The `.get() == nullptr` check skips passes that already have an explicit caster set (none of our materials do, but it's defensive).

Replace that **entire** block (the leading `// Shadows are off pending a working technique.` comment through the `setShadowTechnique(Ogre::SHADOWTYPE_NONE);` line) with:

```cpp
  // Shadows v4 (2026-05-19): SHADOWTYPE_TEXTURE_MODULATIVE with the
  // hand-rolled YARS/TextureShadowCaster (materials/YARSShadowCaster.material).
  // The caster has explicit GLSL programs so RTSS doesn't get involved
  // in the caster pass — that was the root cause of v3 producing visually
  // broken frames (sky-blue + sawtooth, commit a10c1b1). MaterialManager
  // sets setShadowCasterMaterial on every receiver pass. Wrap the
  // technique-enable in try/catch so a material/shader load failure
  // degrades to SHADOWTYPE_NONE rather than crashing the scene.
  try {
    _sceneManager->setShadowTechnique(Ogre::SHADOWTYPE_TEXTURE_MODULATIVE);
    _sceneManager->setShadowTextureSize(1024);
    _sceneManager->setShadowTextureCount(1);
    _sceneManager->setShadowFarDistance(50.0f);
    _sceneManager->setShadowColour(Ogre::ColourValue(0.5f, 0.5f, 0.5f));
  } catch (const std::exception &e) {
    std::cerr << "Failed to enable texture-modulative shadows: "
              << e.what() << " — falling back to SHADOWTYPE_NONE."
              << std::endl;
    _sceneManager->setShadowTechnique(Ogre::SHADOWTYPE_NONE);
  }
```

Note: keep the comment block compact — don't preserve the full archive of past attempts inside the code. The history lives in the spec doc and git log.
