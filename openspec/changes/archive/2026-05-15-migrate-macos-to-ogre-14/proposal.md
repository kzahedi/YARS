# Migrate macOS code paths to Ogre 14

## Why

After the Linux GUI port verification (`add-linux-port-verification`), the
`ext/ogre-source` submodule was advanced to Ogre 14 (commit
`211d902b97fb90e90355f1005faccc2c1bc65a1a`, ~14.4). Linux code paths were
updated to the new APIs; **macOS code paths still target Ogre 13.x APIs**.

The local macOS dev environment works because each contributor has a
cached `ext/ogre/install/` from when the submodule was at 13.6.4. Fresh
clones, CI, and contributors without that cache cannot build on macOS
against the current submodule.

To unblock macOS CI today, `.github/workflows/macos-build.yml` pins the
submodule to `v13.6.4` for that job only. This proposal tracks
eliminating that pin by updating the Apple branches to Ogre 14 APIs.

## What changes

Apple branches currently reference Ogre 13.x APIs that are removed in
Ogre 14:

1. `Ogre::STBIPlugin` (class removed; only `STBIImageCodec` remains)
   — `src/yars/view/gui/OgreHandler.{h,cpp}` and `ShaderManager.h`
2. `Ogre::RTShader::FFPTexturingFactory` (removed from public API)
   — `src/yars/view/gui/ShaderManager.cpp`
3. `OgreShaderFFPTransform.h` (moved to private `src/`)
   — `src/yars/view/gui/ShaderManager.h`
4. `OgreGL3PlusPlugin.h` and `OgreParticleFXPlugin.h` framework paths
   — `src/yars/view/gui/OgreHandler.h` (include resolution differs)
5. `STBI codec` and `FreeImage codec` static plugin loading
   — `src/yars/view/gui/OgreHandler.cpp`
6. Static-link flags in `src/yars/CMakeLists.txt` reference Apple Ogre
   13 file layout (`libOgreMainStatic.a`, frameworks etc.).

The Linux branch already uses dynamic plugin loading via `plugins.cfg`
(generated by `cmake/CreateConfigFiles.cmake` from
`src/cfg/plugins.cfg.in`). The macOS branch should converge on this
pattern: build Ogre 14 dynamic, list the plugins in `plugins.cfg`, and
let `Ogre::Root("plugins.cfg", ...)` auto-load them. This eliminates
the static-link block in `src/yars/CMakeLists.txt` entirely.

## Acceptance

- `ext/ogre-source` submodule stays at Ogre 14
- macOS dev builds compile from a fresh clone (no pre-existing Ogre
  install required)
- `macos-build.yml` no longer pins to `v13.6.4`; the `OGRE_MACOS_TAG`
  env var and the override step are removed
- macOS GUI session (locally on contributor's Mac) still works: window
  opens, scene renders, mouse + scroll input work, screenshot checked
  in to `docs/planning/macos-screenshots/braitenberg.png`
- Single `plugins.cfg` template serves both Linux and macOS

## Out of scope

- Migrating to Ogre 15 / next major
- Replacing Ogre with another renderer
- Refactoring the macOS bundle/packaging story
